Customs ES — Digital Transformation

Government Digital transformation 50+ processes · Dual device

Context

50+ paper processes at El Salvador's customs — no prior interface to redesign.

El Salvador's customs authority ran entirely on paper: declarations, permits, inspections, gate clearances. The project was a complete digital transformation — not a redesign of something that existed, but a first-time design of everything from scratch.

The operation meant two devices at every gate: an agent terminal and an inspector handheld. The entire interaction model had to be derived from how the actual operation worked, not from how a web form would usually look.

Before · After

From paper at the gate to a digital twin of the operation

Before — paper operation
  • All declarations and inspections on physical forms
  • Gate clearance manually logged, no real-time state
  • Errors discovered at end of shift review, not in the moment
  • No cross-reference between agent terminal and inspector handheld
  • Process time bounded by paper handling and manual data entry
After — digital twin
  • All 50+ processes digitized with consistent UI patterns
  • Real-time gate state: terminal and handheld in sync
  • Inline validation at point of entry — errors surfaced immediately
  • Dual-device interface: complementary screens, not duplicated screens
  • Flows derived from the actual operation, not imposed from outside

What I did

Design from the operation outward

01

Operational shadowing

Observed the paper process before opening Figma. Every form field, every handoff between agents and inspectors, every exception case — mapped as they actually happened, not as the brief described them.

02

Process inventory and deduplication

50+ paper processes had significant overlap. Grouped them into a smaller set of digital interaction patterns before designing individual screens. The system before the screens.

03

Dual-device model

Gate clearance required an agent terminal (full-screen desktop) and an inspector handheld (compact, one-handed). Designed as a coordinated system: the terminal is the record, the handheld is the action layer.

04

Handoff and implementation

PrimeNG component library was the implementation stack. Figma components mapped to PrimeNG equivalents — what you design is what gets built, without translation gaps.

PrimeNG — why the implementation stack matters

The development team implemented in Angular + PrimeNG. Designing with PrimeNG's component model in mind — its form layouts, data tables, dialog patterns — meant the Figma handoff translated directly to code without a component-mapping step that introduces drift. The UI that shipped matched the design because the design was built on the same primitives.
