Blockchain 3D — 3D Interface Design

Blockchain / Web3 3D interface Figma → Spline → Unity

// CONTEXT

Figma, Spline, and Unity as one system — not three handoffs.

The brief: a 3D interface for connected blockchain flows, designed phone-first. The constraint that made it interesting: the typical Figma → 3D → engine pipeline breaks at every seam. Each tool speaks a different language and assumes the one before it already solved the interaction model.

The work was treating these three tools as a continuous pipeline — one design decision propagated through all three layers, not translated at each boundary. The result became the foundation for EQUS.

// BEFORE · AFTER

From three isolated tools to a single propagating system

Typical pipeline
  • Figma designs lose interaction intent when handed to 3D artist
  • 3D scenes rebuilt from scratch — no shared material tokens
  • Unity dev receives 3D assets with no documented interaction model
  • Phone UX tacked on after desktop-first 3D scenes are done
  • Blockchain state changes hard-coded, not data-bound
Integrated system
  • Figma defines the interaction model Spline and Unity inherit
  • Material tokens defined once, applied across all three tools
  • Unity receives scenes with documented gesture + state contracts
  • Phone-first from frame one — camera and gesture designed for thumb
  • Blockchain state changes drive scene transitions, not static screens

// PROCESS

Design decisions that propagate

01

Interaction model in Figma, phone-first

Every flow started on the smallest screen. Swipe, tap, pinch — not click. The 3D scenes were designed to respond to gestures, not to expose a 3D viewport in a web page.

02

Spline as a design layer, not a 3D production layer

Used Spline to prototype the 3D transitions and camera behavior before handing anything to Unity. The scene in Spline was a design decision, not a production asset.

03

Unity as the runtime, not the design environment

Scene transitions and state logic were fully specced before Unity received assets. The Unity dev was implementing a documented contract, not interpreting a 3D model.

04

Blockchain state → scene state

Transaction state, confirmation depth, connection status — each drove a visual scene state. The 3D interface was data-driven, not decorative.
