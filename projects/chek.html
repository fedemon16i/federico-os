Chek — Design System Rebuild

Fintech Design system Onboarding · Credit · Debit · Account opening

Context

A fintech app with no shared foundation — rebuilt from tokens up.

Chek is a digital financial app operating in Central America. The product had grown fast and the design system hadn't kept up: inconsistent components, no shared tokens, and every new screen solving the same problems from scratch.

The rebuild covered credit, debit, and account opening — three distinct onboarding flows with different regulatory constraints, user profiles, and risk levels. The financial education layer that came out of this work became Banco Ripley's Corta y Clara program.

Before · After

From scattered screens to a shared language

The before state was invisible — each screen worked, but nothing shared a foundation. The after is a system that drifts less.

Before
  • No shared token layer — colors and spacing hardcoded per screen
  • Three onboarding flows with zero component reuse
  • Error states inconsistent across credit and debit
  • Financial education copy embedded in one-off UI, not a system
  • Handoff to dev: Figma screens with no documented behavior
After
  • Shared design token layer across all three flows
  • Component library: buttons, inputs, cards, alerts — one source
  • Unified error/success/loading states with documented variants
  • Financial education as a modular layer — portable to other products
  • Corta y Clara program adopted by Banco Ripley from this work

What I did

Systems before screens

01

Audit every flow

Catalogued every component across credit, debit, and account opening. Found the real inconsistencies — not just visual, but behavioral: the same action working differently in three places.

02

Token layer first

Color, spacing, radius, shadow — all as named tokens before any component was touched. The token layer is what keeps design and code in sync as the product grows.

03

Components built on the token layer

Rebuilt each component to reference tokens, not raw values. Three flows share the same button, the same input, the same error state — they just override the accent where needed.

04

Financial education layer

Designed the in-app financial education as a modular layer — content blocks that teach without blocking the primary task. This layer was later adapted as Banco Ripley's Corta y Clara program.
